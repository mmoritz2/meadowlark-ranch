# Approved black dragon game rig

This derivative uses the actual Black Dragon by 3DHaupt. It retains the three dragon meshes, 37,986 source triangles, source UVs, material definitions, and all nine embedded texture images. The decorative twelve-triangle showcase floor is excluded from the game asset. The acquired original GLB and receipt remain unchanged.

Source: [Black Dragon with Idle Animation](https://sketchfab.com/3d-models/black-dragon-with-idle-animation-fb0053a2e59b43868e934c239bf4eb36) by 3DHaupt, [CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/) with the source's NoAI requirement. Conversion, skin evaluation, animation baking, and CPU rendering use ordinary numerical tools. No generative image or asset tools are used.

The original glTF default-scene skin is evaluated before conversion. Native Blender import changes that source's initial pose, so review poses are instead evaluated with the vendored Three loader and baked to static meshes before ordinary Blender rendering. Game textures larger than 2048 pixels are conventionally resized with Pillow Lanczos; original source images remain in the immutable source file.

The rig has the shared forty anatomical joints plus twenty-eight retained source wing joints. Original skin ownership is collapsed by anatomical ancestry; real wing ownership stays on the source branches. In the derived skin, the lowest genuine claw/palm points follow the terminal hoof joint, tapering smoothly back to the source ankle/hand blend between 0.06 m and 0.16 m above each low foot surface. This source-specific weight adaptation preserves exact rest geometry, UVs, indices, and all original source files. The +Z-forward, +Y-up body is uniformly normalized to 1.85 m at the torso withers, excluding wing fingers and horns from the withers measurement. Its source-open bounding height is 3.19074 m. The physicalScale profile flag and fitScale=1 / fitY=0 keep the normalized dragon at its actual 1.85 m torso withers, preventing an inner loader fit from shrinking it to 1.45 m or old breed size modifiers from stretching it. Anchors use the unscaled body coordinates and must follow the bound spine/head as appropriate.

Live motion is provided by `assets/dragon-horse-motion.js`. Use `createDragonMotion({THREE,root:rig.scene,skin,heightM:profile.heightM,profile})`, then the same ground `set(gait,{lead})`, `setTurn(turn)`, and `update(dt)` API as the anatomical horse core. Before a flight update, call `setFlight({flying,altitude,verticalSpeed,speedMps})` with the character's own physical state. Flight uses elapsed time directly; the ground stride speed multiplier should not accelerate flight staging. The native dragon body and wings replace generated horse crest/wing overlays. Preserve the authored saddle anchor and source groom flag.

The stirrup anchors retain the generated English saddle's tread plane at raw saddle Y−0.512 m and Z+0.200 m. An exact horizontal ray through source torso-owned triangles measures a 0.748116 m barrel width there; the usual ±0.270 m treads would enter the torso by about 0.104 m. The profile moves only their X coordinates to −0.408979 m and +0.409137 m, giving each side 35 mm clearance while preserving tread height and forward reach. `stirrup-fit.json` records the source ray, raw coordinates, and ownership threshold. These anchors must follow the bound torso along with the saddle.

The actual source claws extend beyond horse hoof dimensions. A source-specific contactEnvelope selects broad claw points within 0.65 m radius and 0.14 m above the terminal, preserving the original sole marker. The solver uses their real blended skin positions to resolve floor clearance without stretching anatomical limb lengths. This opt-in setting is confined to the dragon profile.

Twelve baked clips provide Rest, Idle, Walk, Trot, Canter_Left, Canter_Right, Gallop_Left, Gallop_Right, Jump, Takeoff, Fly, and Land. Ground clips are sampled at 240 Hz and flight clips at 60 Hz. They are independent game motions; the source's original animation remains available in the immutable acquisition. The live adapter opens the shoulders before unfolding the fingers, flaps the real membranes, tucks the legs with altitude, and extends them for landing. Ground folding uses only rotations at unit bone scale. Actual wing and tail surface samples drive small shoulder and tail-root rotations when needed for floor clearance, including jump crouches; their source geometry stays intact. Ground wing idle motion shares the body/gait period, allowing an exact anatomical loop without blending planted feet or sweeping appendages below the floor.

`motion-qa.json` verifies the actual loaded skin: both leads, all ground modes including progressing jump, fixed limb lengths, claw target/reach errors, finite flight transforms, paused refresh stability, twelve playable clips through AnimationMixer, every vertex of the actual three-mesh surface measured at 240 Hz through all ground clips, and wing clearance against a spine-following rider torso envelope during sampled takeoff/landing transitions. It does not replace a mounted-rider review in the running site. The ordinary material renders are in `review/`; mounted runtime integration is tracked separately by the main project's integration review.

`performance.json` records 1,000 positive 1/60-second live updates per mode, following 120 warmup steps and excluding parsing and adapter construction. The full adapter averaged 2.48–2.77 ms per update in Node on this computer. Its exact wing/tail guard added about 0.54 ms in gallop and 0.33 ms in flight compared with the same adapter with only that guard disabled. The stand comparison has process-order/JIT noise. These are CPU motion timings, not a browser rendering frame budget; source geometry, the exact surface guard, and current contact guarantees stay intact. Run `node tools/benchmark-imported-dragon.mjs` to repeat the measurement.

Rebuild, in order:

```sh
python3 tools/asset-gen/rig-imported-dragon.py
node tools/bake-imported-dragon-clips.mjs
node tools/qa-imported-dragon.mjs --write-poses --dense-clips --full-surface
```

The bake tool requires the freshly rebuilt derivative and refuses to append a second set of clips. Source SHA256, output SHA256, texture changes, and motion code hashes are recorded in the adjacent reports. This provides a shared game rig and visible equestrian behavior; it does not reproduce an unpublished Star Equestrian proprietary skeleton hierarchy.
